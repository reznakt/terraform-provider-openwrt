# OpenWrt Provider

Manages OpenWrt routers through the ubus JSON-RPC API that uhttpd serves at
`/ubus` (the same API LuCI uses). No agent, no SSH.

* **Typed resources** for network, wireless, firewall, DHCP/DNS, system and
  services, with validation and import, plus `openwrt_uci_section` for any
  other UCI section.
* **Rollback protection**: every change is applied with `uci apply` and a
  rollback timer. The provider confirms it over a fresh connection; if the
  change cut off access (wrong LAN address, firewall, uhttpd settings), the
  router reverts on its own and the resource fails with `change rolled back`.
* **Secrets** never appear in plan output, and with the `*_wo` write-only
  attributes never in state either. See the [secrets guide](guides/secrets.md).

## Requirements

* OpenWrt with LuCI; tested with 24.10 (it brings `uhttpd-mod-ubus`, `rpcd`,
  `rpcd-mod-file` and `luci-app-package-manager`).
* An rpcd login for the provider; see the [router setup guide](guides/router-setup.md).
* Terraform or OpenTofu >= 1.11 for write-only attributes.

## Semantics

* A typed resource owns the options it declares: an attribute left unset
  means the option is removed from the router. Options it does not declare
  are left alone unless listed in `extra_options`/`extra_lists`.
* `openwrt_uci_section` owns the whole section.
* Sections that exist on every stock router (`openwrt_system`,
  `openwrt_firewall_defaults`, `openwrt_dhcp_dnsmasq`, radios, ...) are
  adopted on create and only forgotten on destroy.
* Anonymous sections are imported as `@type[index]` and renamed to the
  resource's `section` on the next apply.
* Changes are serialized: the router supports only one pending rollback, so
  each resource change is applied and confirmed on its own.

## Example Usage

```terraform
provider "openwrt" {
  endpoint = "https://192.168.1.1"
  username = "terraform"
  # Password from OPENWRT_PASSWORD or a file managed by sops/agenix:
  password_file = "/run/secrets/openwrt-terraform"

  # Trust the router's certificate instead of disabling verification.
  ca_cert = file("${path.module}/router-ca.pem")

  # Every change is confirmed or rolled back by the router within 30s.
  apply_timeout = 30
}
```

## Schema

### Optional

- `apply_holdoff` (Number) Seconds to wait after applying before confirming, so services have reloaded. Default 4.
- `apply_timeout` (Number) Seconds the router waits for confirmation before rolling a change back. Default 30.
- `ca_cert` (String) PEM certificate(s) to trust, e.g. the router's `/etc/uhttpd.crt`. Env: `OPENWRT_CA_CERT`.
- `endpoint` (String) Router URL, e.g. `https://192.168.1.1` (`/ubus` is appended when the path is empty). Env: `OPENWRT_ENDPOINT`.
- `insecure` (Boolean) Skip TLS verification (the router's self-signed certificate). Env: `OPENWRT_INSECURE`. Prefer `ca_cert`.
- `password` (String, Sensitive) rpcd login password. Env: `OPENWRT_PASSWORD`. Prefer `password_file` or the environment over literals.
- `password_file` (String) Path to a file containing the password (trailing newline ignored), e.g. from sops or agenix. Env: `OPENWRT_PASSWORD_FILE`.
- `request_timeout` (Number) Timeout of a single API request in seconds. Default 30.
- `rollback` (Boolean) Apply changes with `uci apply` rollback protection. Default true. When false, changes are committed and `reload_config` is called directly.
- `username` (String) rpcd login name. Defaults to `root`. Env: `OPENWRT_USERNAME`.
